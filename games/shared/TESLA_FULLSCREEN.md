# Tesla Cybertruck chromeless fullscreen

## Mechanism

Tesla’s in-car browser (including Cybertruck) keeps the address bar / toolbar on ordinary navigations. The same workaround used by Fullify, TeslaTube, and FullscreenTesla applies here:

1. Navigate to `https://www.youtube.com/redirect?q=<ENCODED_ABSOLUTE_GAME_URL>`.
2. YouTube’s interstitial asks to leave YouTube; confirming opens the target **without** the Tesla browser chrome (fullscreen / theater-style).

Similarize bakes this into each live cab so drivers do not have to paste a YouTube redirect by hand.

## Shared helper

File: `games/shared/tesla-fullscreen.js`  
API: `window.SimilarizeTeslaFS = { maybeRedirect(), isTesla(), alreadyFullscreen() }`  
Auto-runs `maybeRedirect()` on load.

### UA / force detection (`isTesla()`)

Likely Tesla when the user-agent matches:

- `QtCarBrowser` (classic Tesla car browser)
- `\bTesla\b` (modern Chromium builds often include `Tesla/YYYY.MM…`)

**Force for testing (desktop):**

- Query: `?tesla=1`
- Or `localStorage.setItem('similarize_tesla_fs', '1')` then reload

### Anti-loop (`alreadyFullscreen()` + session)

Redirect runs only when Tesla **and** not already fullscreened:

| Guard | Behavior |
| --- | --- |
| `tesla_fs=1` in the game URL | Skip — we append this flag to the `q=` target before redirecting |
| `document.referrer` contains `youtube.com` | Skip — landed via the YouTube redirect |
| `sessionStorage` key `similarize_tesla_fs_done:<pathname>` | Skip — already redirected this tab session for this path |

Desktop / non-Tesla: **no-op** (no endless redirects).

### Target URL

Built from `location.href`:

- Absolute URL (so relative assets resolve on the same origin after landing)
- Prefer `https://` for `*.similarize.com`
- Preserve existing query (party `room=`, etc.)
- Add / set `tesla_fs=1`
- Strip `#hash` noise

Encoded into: `https://www.youtube.com/redirect?q=` + `encodeURIComponent(absoluteUrl)`.

## Drop-in for a new game

In the live entry HTML, **before** gamepad / game scripts (ideally early in `<head>`):

```html
<!-- Tesla Cybertruck chromeless FS — see games/shared/TESLA_FULLSCREEN.md -->
<script src="../shared/tesla-fullscreen.js?v=tfs1"></script>
```

Use `shared/…` or `../shared/…` depending on whether the HTML lives in `games/` or a subdirectory. Bump `?v=` when the helper changes.

Pure redirect stubs (`Rally.html`, `froggies-cybertruck/`, `map*.html`) do **not** need the script; the final destination cab handles FS.

## Publish note

`games/shared/` must stay live on production (`tesla-fullscreen.js` + `gamepad.js`). Arcade index may keep linking to plain game URLs; the redirect happens on game load so desktop arcade stays clean.

## Known caveats

- **YouTube must be reachable** in the car (network / region). If YouTube is blocked, the redirect interstitial never appears.
- **First paint may flash** before the script runs and `location.replace` fires. Keep the script early in `<head>` to minimize this.
- **Manual confirm:** Tesla/YouTube may still show a “go to site” interstitial once; that is expected.
- **Referrer / third-party quirks:** Some privacy modes strip `document.referrer`. The `tesla_fs=1` flag and sessionStorage guards still prevent loops.
- **Service workers:** After redirect lands, the document URL is again the game’s absolute Similarize URL, so SW scope (if any) matches the game origin/path as usual. Do not register a SW scoped only to a youtube.com URL.
- **Party / invite links:** Existing query params are preserved when adding `tesla_fs=1`. Invite URLs generated by the game should remain plain Similarize URLs (not pre-wrapped in YouTube); guests in a Tesla will auto-redirect on load.
